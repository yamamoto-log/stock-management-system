# 着物レンタル店向け在庫管理Webアプリ 要件定義書（たたき台）

Oct 8, 2026

## 1. アプリの目的と達成状態

本システムは、着物レンタル店における商品在庫を、拠点・箱単位で一元管理することを目的とする。

店舗ごとの在庫数だけでなく、商品がどの拠点のどの箱に保管されているかまで管理することで、離れた場所に保管されている商品についても、現地へ確認しに行くことなく保管状況を把握できるようにする。

また、入出庫や拠点間の移動、保管場所変更を記録し、在庫数の変化を追跡可能にすることで、在庫差異が発生した際の原因を確認できる仕組みを構築する。

これにより、「どの商品が、どこに、何個あるのか」を正確かつ効率的に把握できる在庫管理環境を実現する。

**主軸**：所在把握（どこに何があるかを探せること）を第一の価値とし、差異の原因追跡をそれに次ぐ価値とする。機能の優先度で迷った場合は、所在把握に役立つ方を優先する。

### 達成状態（成功の基準）

- 商品を検索すると、拠点ごと・箱ごとの数量が分かる
- 箱IDから、箱を開けずに中身が分かる
- 在庫数が変わるすべての操作が、日時・操作者つきで記録されている
- 発送したのに受け取られていない移動があれば、それが分かる

## 2. 背景と業務上の課題

着物レンタル店ではオールシーズンの商品を保管する必要があるが、店舗によっては保管スペースが不足する。そのため、オフシーズンの商品を本部へ送って保管している。この運用の中で、次の課題が発生していた。

| No. | 課題 | 分類 |
| --- | --- | --- |
| P1 | 本部のどの箱に何が入っているか分からない | 所在把握 |
| P2 | 箱のラベルが手書きで、表記が統一されていない | 所在把握 |
| P3 | 箱を開けないと中身が分からない | 所在把握 |
| P4 | 店舗間で送った商品が届いたか確認しにくい | 所在把握 |
| P5 | 忙しいときに商品を出しても記録されない | 記録・追跡 |
| P6 | Excelの在庫数と実際の数量が合わなくなる | 記録・追跡 |
| P7 | 数量が合わなくなった原因を追跡しにくい | 記録・追跡 |
| P8 | 他店舗・本部の在庫を確認するには現地へ行く必要がある | 所在把握 |

## 3. 利用者と前提条件

### 利用者

| 役割 | 想定する人 | できること |
| --- | --- | --- |
| 一般 | 社員 | 全拠点の閲覧、全拠点の在庫操作 |
| 管理者 | マネージャー | 一般のすべて＋商品・拠点・ユーザーの管理 |

アルバイトなど社員以外は利用者に含めない。

### 前提条件

- **在庫数は会社が所有している商品の数とする。** レンタル中・クリーニング中の商品も、元の保管場所の在庫に含める。
- 在庫数は画面から直接編集せず、入庫・出庫・在庫調整・移動などの操作によってのみ変化する。
- 個体管理は行わない。同じ商品（同じ商品コード）はどれも区別しない。
- 新商品は、マネージャーが購入して本部で登録・入庫し、必要に応じて店舗へ移動する運用とする。
- 本部と店舗で在庫の扱い・操作は区別しない。
- 店舗内の細かい場所（店頭・倉庫・バックヤード）は管理しない。

## 4. 用語集

資料・画面・テーブル名・カラム名はこの用語に統一する。「本社」は使わず「本部」とする。「店舗間移動」は本部を含まないように読めるため、「拠点間の移動」とする。

| 用語 | 意味 |
| --- | --- |
| 拠点 | 在庫を管理する単位。奈良店・大阪店・本部など |
| 商品 | 在庫として数える単位。サイズ違い・色違いは別商品 |
| 箱 | 商品を保管する単位。1つの箱に複数種類の商品を入れられる。所属拠点を1つ持つ |
| 箱なし | 箱に入っていない状態。各拠点に1つずつある特別な箱として扱う |
| 保管場所 | 箱または箱なしのこと |
| 入庫 | 新しく仕入れた商品・初期在庫を登録し、在庫を増やす操作 |
| 出庫 | 廃棄・売却・紛失など、商品が会社の在庫から永久になくなることを記録する操作 |
| 在庫調整 | 記録と実物の差異を修正する操作 |
| 保管場所変更 | 同じ拠点内で、商品を別の保管場所へ移す操作。在庫数は変わらない |
| 商品移動 | 保管場所から商品を取り出し、別の拠点へ送る操作 |
| 箱ごと移動 | 箱そのものを別の拠点へ送る操作。箱IDと中身は変わらない |
| 発送 | 商品移動・箱ごと移動で、送り元が送り出すこと |
| 受取確認 | 送り先で検品が完了したことを記録すること |
| 輸送中 | 発送済みで受取確認前の状態。どの拠点の在庫にも含めない |
| 廃番 | 商品の利用停止 |

## 5. 課題と機能の対応

各機能がどの課題を解決するかを示す。どの課題にも対応しない機能は、MVPに含める理由を改めて検討する。

| 機能 | 内容 | 対応する課題 |
| --- | --- | --- |
| 箱の在庫管理 | 箱ごとに中身と数量を記録し、箱IDから中身を確認できる | P1・P3 |
| 箱IDの自動採番 | 全拠点通し番号のIDをシステムが発行し、ラベルに記入する | P2 |
| 在庫検索 | 商品から、拠点別・箱別の数量を確認できる | P1・P8 |
| 全拠点の閲覧 | すべての利用者が全拠点の在庫を確認できる | P8 |
| 入庫・出庫・在庫調整 | 在庫の増減を理由つきで記録する | P6・P7 |
| 保管場所変更 | 同一拠点内で箱・箱なしの間を移す | P1・P3 |
| 商品移動・箱ごと移動 | 拠点間の移動を発送・受取の2段階で記録する | P4・P6 |
| 受取待ちの表示 | 未受取の移動を送り先・送り元の両方に表示する | P4 |
| 操作履歴 | 在庫に影響するすべての操作を、日時・操作者つきで記録する | P5・P7 |
| 全拠点での操作 | 応援先でも操作でき、その場で記録できる | P5 |
| ログイン・権限 | 操作者を特定し、マスタの管理を管理者に限定する | P2・P7 |

## 6. 業務ルール

各ルールには、面接で説明できるよう理由を併記する。

### 6-1. 在庫の持ち方

- すべての在庫は「箱 × 商品 × 数量」で管理する。
- 箱なしも、各拠点に1つずつ存在する特別な箱として扱う。
- 拠点の情報は箱だけが持ち、拠点別の在庫数は集計で求める。
- 数量はマイナスにならない（PHPのチェックに加え、DBの制約でも保証する）。
- 数量が0になった「箱 × 商品」の行は自動で削除する。
- 在庫を変更する処理はトランザクションで行う。

**理由**：在庫数を1か所でしか持たないため、拠点合計と箱内数量の不一致が構造上起こらない。箱ごと移動は箱の所属拠点を変えるだけで完結する。「箱なしも保管場所の一つ」という現場の考え方とも一致する。

### 6-2. 入庫・出庫・在庫調整

| 操作 | 保管場所の指定 | 理由の選択肢 |
| --- | --- | --- |
| 入庫 | 入れる先を選択（初期値：箱なし） | 新規購入・初期登録・その他 |
| 出庫 | 在庫がある保管場所から選択 | 廃棄・売却・紛失・その他 |
| 在庫調整 | 調整する保管場所を選択 | 理由の入力は必須。関連する移動を任意で記録 |

- 1回の操作で複数の商品を扱える。1明細につき保管場所は1つとする。
- 出庫はレンタルでの貸出を記録しない。
- 入庫で新しい箱に入れる場合は、箱なしに入庫してから保管場所変更する。

### 6-3. 保管場所変更

- 同じ拠点内で、移動元1つ・移動先1つ・商品は複数選択可とする。
- 移動元と同じ保管場所は移動先に選べない。
- 移動先で「新しい箱」を選ぶと、その場で箱が作成される。
- 箱の統合は、全商品を別の箱へ移し、空になった箱を廃止することで行う。

### 6-4. 拠点間の移動

| 項目 | ルール |
| --- | --- |
| 種類 | 箱ごと移動／商品移動の2種類 |
| 送り元の指定 | 箱ごと移動は箱（複数可）。商品移動は明細ごとに保管場所・商品・数量 |
| 在庫を動かす時点 | 発送時に送り元から減らし、受取確認時に送り先へ加える |
| 輸送中 | どの拠点の在庫にも含めず、「輸送中」として表示する |
| 輸送中の箱 | 中身の変更（保管場所変更・出庫・送り元への指定）を禁止する |
| 受取確認 | 検品完了時に行う。全数受取のみ |
| 受取時の置き場所 | 商品移動は箱なし。箱ごと移動は箱のまま |
| 受取後の整理 | 受取記録から保管場所変更へ進める（入力済みの状態で開く） |
| 検品時の差異 | 受取後に在庫調整で修正する（送り元・送り先の両方を想定） |
| 取消 | 受取前のみ可能。元の保管場所に戻す（使えない場合は箱なし）。取消済みとして記録を残す |
| 二重加算の防止 | 状態を条件にした更新とトランザクションで防ぐ |
| 受取待ちの表示 | 送り先には受取待ち、送り元には未受取の一覧を表示する |

**運用の目安**：複数の商品を梱包して送る場合は、送り元で1つの箱にまとめてから箱ごと移動する。商品移動は、手で運ぶなど少量を箱に入れずに移動する場合に使う。受取確認は送り先拠点、取消は送り元拠点が行うことを運用ルールとする（システムでは制限しない）。

**理由**：受取確認を検品後とするため、発送時に送り先へ加えると、未検品の商品が送り先の在庫に表示されてしまう。

### 6-5. 箱

- 箱IDは全拠点の通し番号とし、主キーから表示コードを生成する（例：BOX-0015）。欠番は許容する。
- 箱は保管場所変更の移動先で作成する。事前作成の機能は持たない。
- 箱の状態は、使用中・輸送中・廃止の3つとする。
- 「空」は保存せず、中身の行が1つもないことで判定する。空の箱は自動で廃止しない。
- 廃止は空の箱に限り行える。削除はせず状態を変える。
- 段ボールを交換しただけなら箱IDを引き継ぐ。システム上の操作は不要。
- 箱なし用の箱は、コードを表示せず「箱なし」と表示する。箱一覧に出さず、箱ごと移動・廃止の対象にしない。

**理由**：現場では詰め終わってからラベルを書くため、移動と同時に箱を作り、表示されたIDをラベルに記入する流れにする。

### 6-6. 拠点

- 拠点は、拠点名（重複禁止）・備考・状態（利用中／停止中）を持つ。
- 拠点を登録すると、箱なし用の箱を同時に作成する。
- 停止は、在庫・使用中の箱・輸送中の移動・所属ユーザーがすべてない場合のみ可能とする。
- 停止中の拠点は選択肢に出さないが、履歴には表示する。再開もできる。
- 拠点名を変更すると、過去の履歴にも新しい名前で表示される。

**理由**：拠点種別・住所・電話番号は、使う機能がないため持たない。

### 6-7. 商品

| 項目 | 入力 | 備考 |
| --- | --- | --- |
| 商品コード | 自動 | 主キーから生成（例：P-0123） |
| 商品名 | 必須 | 重複を許可（サイズ違いで同名になるため） |
| カテゴリ | 必須・選択式 | 初期データはSQLで登録。管理画面なし |
| 色・柄・サイズ | 任意・自由入力 | 検索は部分一致 |
| 画像 | 任意 | 1商品1枚 |
| 備考 | 任意 | 自由入力 |
| 状態 | — | 利用中／廃番 |

- サイズ違い・色違いは別商品とし、サイズごとに1行持つ。
- 廃番は、在庫と輸送中の移動がない場合のみ可能とする。

### 6-8. 権限

| 操作 | 一般 | 管理者 |
| --- | --- | --- |
| 全拠点の閲覧 | ○ | ○ |
| 在庫操作（全拠点） | ○ | ○ |
| 商品の登録・編集・廃番 | × | ○ |
| 拠点の管理 | × | ○ |
| ユーザーの管理 | × | ○ |

- ユーザーは所属拠点を1つ持つ。入力の初期値とダッシュボードの表示に使う。
- 所属拠点以外を操作する場合は、確認画面で注意を表示する。
- 退職者は削除せず利用停止とする（ログイン不可、履歴には名前が残る）。

**理由**：応援先で操作できないと入力漏れの原因になるため、操作を制限せず、操作者の記録によって追跡する。商品名を統一するため、商品の登録は管理者に限定する。

### 6-9. 履歴

- 在庫に影響する操作（入庫・出庫・在庫調整・保管場所変更・発送・受取・取消・箱ごと移動）を記録する。
- 記録には、日時・操作者・拠点・箱・商品・数量・理由を含める。
- マスタの変更履歴は記録しない。
- 移動の管理と操作履歴は、同じ「在庫操作」の記録で兼ねる方針とする（詳細はDB設計で確定）。

## 7. 対象外とする機能

MVPでは在庫・箱管理に集中し、以下は意図して対象外とする。

| 機能 | 対象外とする理由 |
| --- | --- |
| 予約管理・予約可能数の計算 | 在庫・箱の所在把握に集中するため |
| レンタル中の状態管理 | 予約管理と一体であり、在庫数は所有数として扱うため |
| クリーニング管理 | 同上 |
| 個体番号による1点単位の管理 | 現物にタグがなく、運用負荷が大きいため |
| 足袋などの消耗品 | 渡した時点で記録できず、システム化しても在庫がずれるため |
| 店舗内の細かい場所の管理 | 拠点と箱の単位で目的を満たせるため |
| 受取時の数量入力・置き場所の分割 | 差異はまれで、受取後の在庫調整・保管場所変更で対応できるため |
| マスタの変更履歴 | マスタを編集できるのは管理者のみで、必要性が低いため |
| カテゴリの管理画面 | 追加がまれで、SQLで対応できるため |
| 拠点の住所・電話番号・種別 | 使う機能がないため |
| AIによる柄認識・画像認識 | MVPの目的に不要なため |
